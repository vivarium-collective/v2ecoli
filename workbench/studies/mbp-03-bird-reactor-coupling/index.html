Question & approach

Question. Can v2ecoli (with the mbp-01 time-varying-env hook and mbp-02 population aggregator) be coupled to `pbg-bioreactordesign`'s BiRDReactorProcess — via a thin adapter that resolves the biomass-ownership conflict between the two — such that BiRD supplies dissolved O2, kLa, gas-phase physics, and v2ecoli supplies population biomass and exchange-flux demand, producing a physically consistent coupled trajectory in a 0D well-mixed bench-scale reactor?
Hypothesis / Expected outcome. DO drops below saturation as v2ecoli's population consumes O2; raising kLa raises steady-state DO. Reactor biomass concentration tracks v2ecoli's population growth. With cells removed (population aggregator returning zero), DO converges to BiRD's Henry-saturation. Coupled run completes one v2ecoli generation (~60 min) without state divergence.
Mechanism / Model change. pbg-bioreactordesign's `BiRDReactorProcess` provides 0D well-mixed reactor physics (Higbie kLa, temperature-dependent Henry's law, Wilke-Chang diffusivity, gas-holdup) but ALSO carries an internal biomass ODE driven by its own Monod kinetics. v2ecoli owns biomass via per-cell mass and Division. **Option-B resolution (adopted 2026-05-26 per chris_feedback_2026_05_26 §5 + §11; Eran's decision).** Rather than disabling BiRD's internal biomass ODE behind a `bird_disable_internal_biomass=true` flag, fork upstream a new `BiRDTransportProcess` that omits the biomass equation entirely. Rationale: - Substitutability symmetry: the cell-side interface contract makes cell-side engines variable while the reactor side stays fixed; forking gives two reactor variants (with internal biomass for standalone use; without it under the contract). Story symmetric across both sides. - Naming: a `disable X` flag signals "shouldn't be there in the first place" rather than "let users turn it off." - Tested-vs-dead-code paths: with `disable=true` the biomass-ODE code path exists but isn't exercised under this configuration; untested in this regime, no signal if it later quietly breaks. Done well, Option B is NOT "copy `BiRDReactorProcess` and delete the ODE." It's extract-shared-transport-module — kLa / Henry / Wilke-Chang in a shared module, with `BiRDReactorProcess` and `BiRDTransportProcess` as two consumers (preserves DRY while delivering the design benefit). **Cross-investigation dependency:** the fork lives upstream in `vivarium-collective/pbg-bioreactordesign`. mbp-03 entering Build phase is BLOCKED on `pbg-bioreactor-transport-fork` (pre-seeded as a candidate-future-study in mbp-06; effectively a hard prereq, see pipeline_gate.prerequisites below). Coupling actions, given `BiRDTransportProcess`: (1) **Drive BiRDTransportProcess's biomass-input port with v2ecoli's aggregated population** via a `ReactorCellCoupler` Step that writes `reactor.biomass = population.biomass_concentration_gL` each step. (2) **Drive v2ecoli's environment with BiRD's dissolved-phase**: coupler writes BiRD's `dissolved_o2` / `dissolved_co2` into v2ecoli's `environment.external_concentrations.OXYGEN-MOLECULE[p]` / `CARBON-DIOXIDE[p]` (units conversion mg/L → mM). (3) **Drive BiRD's O2 demand with v2ecoli's metabolism**: coupler aggregates v2ecoli's `external_exchange_fluxes.OXYGEN-MOLECULE[p]` across agents × biomass and writes it as BiRD's `o2_uptake_rate` input. (4) **Drive BiRD's CO2 demand with v2ecoli's metabolism**: symmetric to (3) — `external_exchange_fluxes.CARBON-DIOXIDE[p]` → `co2_production_rate`. Result: BiRDTransportProcess = transport-only physics; v2ecoli = biology + biomass. The coupling is the minimal adapter on the v2ecoli side; reactor-side cleanup is upstream.
Summary. Four-way coupling: (1) population biomass -> reactor.biomass; (2) dissolved O2/CO2 (mg/L->mM) -> v2ecoli environment; (3) aggregated metabolism O2 uptake -> BiRD O2 demand; (4) metabolism CO2 production -> BiRD CO2 demand. Expected biology: DO drops below Henry saturation as cells consume O2; dissolved CO2 rises above saturation; higher kLa raises DO and strips CO2; no-cells runs reach Henry equilibrium.

Plan & assumptions

Pipeline gate

Each study is a model-building gate: it answers "Can we safely build the next layer?"

Prerequisites: none (root study)
Proceed when: Coupling direction tests pass (DO drops with cells, dissolved CO2 rises with cells, higher kLa lifts DO and lowers dissolved CO2); no-cells runs reach Henry equilibrium for both O2 and CO2; one v2ecoli generation completes without state divergence; O2 mass-balance test closes (previously referenced by the gate but not actually implemented in the test set — chris_feedback_2026_05_26 §7 consistency fix).

Key assumptions

  • 0D well-mixed reactor; bubble column geometry as the default for mbp-03 (per BiRD's default). Stirred-tank may be required for mbp-05 Beulig matching — see open_question reactor-geometry-for-beulig.
  • BiRDTransportProcess (Option-B fork) has no internal biomass ODE; v2ecoli's population is the SOLE source of biomass truth — by construction, not by flag.
  • v2ecoli's per-cell μ from metabolism — when aggregated by cells_per_agent — captures the same physics BiRD's Monod would have approximated.
  • Timestep: sim duration 240 min (4 BiRD ticks at 1-h default) chosen so 'second-half steady-state' windows are meaningful. If BiRD's interval is tunable in the fork (open_question coupler-timestep-tunability), drop to ~minutes and tighten tolerances.

Limitations

What this study explicitly does NOT validate (prevents overclaim).

  • Uses BiRDTransportProcess from the upstream `pbg-bioreactor-transport-fork` PR — until that lands and is pinned, mbp-03 cannot enter Build phase.
  • Single v2ecoli generation only (or, in chris_feedback_2026_05_26 §6 terms, 4 BiRD ticks); multi-generation stability is mbp-04's scope.
  • Bubble column geometry default; stirred tank / airlift not validated this phase. May need switch for Beulig matching (open_question reactor-geometry-for-beulig).
  • Fed-batch operations not supported (pbg-bioreactordesign has no fed-batch yet) — flagged as a deferred enhancement; mbp-05 may stress this.
  • Coupler timestep mismatch (BiRD ~1 h default, v2ecoli ~1 s): the coupler holds last-known BiRD state between BiRD ticks. Mitigated to acceptable by 240-min default sim duration (4 ticks). Open_question coupler-timestep-tunability tracks the path to BiRD-interval-as-tunable in the upstream fork.
