1. What changed in the code

BEFORE — strategy classes

One host process PolypeptideElongation(PartitionedProcess) (~1342 lines) held all scaffolding and delegated the five elongation hooks to a plain-object strategy model chosen at runtime by config flags:

if trna_charging:
    self.elongation_model = SteadyStateElongationModel(...)
elif translation_supply:
    self.elongation_model = TranslationSupplyElongationModel(...)
else:
    self.elongation_model = BaseElongationModel(...)

Models lived in polypeptide/elongation_models.py (~755 lines) and reached the host via self.process.X.

AFTER — wireable process chain

Three sibling PartitionedProcess classes via inheritance, all in polypeptide_elongation.py (~1811 lines):

BasePolypeptideElongation
  └─ TranslationSupplyPolypeptideElongation
       └─ SteadyStatePolypeptideElongation

elongation_models.py deleted (−855 lines). The trna_charging/translation_supply flags are gone; the variant is selected by wiring:

composites/_helpers.py:
 'ecoli-polypeptide-elongation': SteadyStatePolypeptideElongation

The baseline composite runs the SteadyState (tRNA-charging) model in both versions — BEFORE via the default trna_charging=True flag, AFTER via the hard-wired class. So a faithful comparison must hold the model fixed; see Methodology.

Methodology

  • Both versions built their runtime cache from the same shipped ParCa fixture (models/parca/parca_state.pkl.gz); the resulting initial_state.json is byte-identical (md5 verified), so molecular inputs are held constant.
  • Each version runs its own canonical baseline (SteadyState charging model), seed 0, 3 generations, via v2ecoli-workflow with the ParquetEmitter.
  • Outputs aligned on (generation, global_time); every listeners__* column written by the elongation process (plus global mass/growth) is compared element-wise (scalars and per-amino-acid arrays).
  • "Within 1e-6" treats sub-microscopic differences as floating-point noise from reordered arithmetic.
  • Caveat (multi-generation realism): the cache is built from the committed ParCa fixture (models/parca/parca_state.pkl.gz) via build_cache.py. Generation 0 divides naturally at ~2528 s (inside the model's expected 2400–2700 s band). Daughters (gens 1–2) grow past a full doubling (2.17× and 2.29×) but do not re-initiate division within the max_duration_per_gen=3600 s cap — a replication-initiation limitation of the committed debug-grade fixture (see the AGENTS.md note on fast/debug ParCa). This is a property of the fixture, present identically in both runs, so it does not affect the before/after conclusion; it only means "3 generations" here = one natural division plus two capped over-growth slots.
  • Confound found & controlled: an initial attempt ran BEFORE against a cache built by AFTER's build_cache.py, whose sim_data.py had dropped the now-dead trna_charging/translation_supply config keys. BEFORE then defaulted those flags to False and silently ran the non-charging Base model, producing large spurious "deviations". Rebuilding BEFORE's own canonical cache (with trna_charging=True) — while verifying initial_state.json stayed byte-identical — restored the apples-to-apples comparison reported here.
