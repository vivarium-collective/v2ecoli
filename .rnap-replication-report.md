# RNAP placement + replication state wiring — feat/parsimony-relax-wiring

## Status
DONE. Precise RNAP genomic placement and live replication state (chromosome
copy count + fork progress) are now wired from the LIVE simulation state into
the v2ecoli 3D structural pack, as the default (no config flag — always on
when the data is present; falls back to the prior generic behavior when it
isn't).

## What changed
- `v2ecoli/structural/build.py`: ported `classify_domains` (+ helper
  `_descendant_domains_set`) verbatim from
  `origin/feat/3d-transcription-translation`; added new live-state helpers
  `chromosome_state_from_live(full_chromosome, active_replisome=None) ->
  (n_chromosomes, fork_fraction)` and `rnaps_from_live(active_rnap,
  full_chromosome=None, chromosome_domain=None) -> list[dict]` (adapted from
  that branch's npz-reading `chromosome_state`/`rnap_state`, but reading
  in-memory unique-molecule structured arrays directly, filtering
  `_entryState` the way `v2ecoli/bridge.py` and
  `scripts/capture_structural_snapshot.py` do). `pack_from_state(...)` gained
  `rnaps=None, n_chromosomes=1, fork_fraction=0.0` kwargs threaded into the
  `Chromosome(...)` constructor (`rnap_marker="rna_polymerase"`,
  `fork_marker="replisome"`, `oric_marker="oriC"`, `ter_marker="terminus"`);
  `supercoil=None` (diffuse nucleoid) is unchanged/preserved. `GENOME_BP`/
  `REPLICHORE_BP` constants added.
- `v2ecoli/structural/pack_step.py`: `EcoliPackStep.inputs()` gained three
  real v2ecoli domain-type ports — `active_RNAP`, `active_replisome`,
  `chromosome_domain` (all registered in
  `v2ecoli/library/schema_types.py:BIOLOGICAL_UNIQUE_TYPES`, so no `"object"`
  fallback was needed). `update()` now computes `n_chromosomes`/
  `fork_fraction`/`rnaps` from these ports each firing tick and passes them
  into `pack_from_state(...)`.
- `v2ecoli/composites/baseline_parsimony.py`: wired the three new ports to
  their live stores, mirroring the existing `full_chromosome` mapping:
  `active_RNAP -> ["unique","active_RNAP"]`, `active_replisome ->
  ["unique","active_replisome"]`, `chromosome_domain ->
  ["unique","chromosome_domain"]` (store paths confirmed against
  `v2ecoli/composites/_helpers.py`, matching every other consumer of these
  stores).
- `tests/structural/test_replication_state.py` and
  `tests/structural/test_pack_step_rnap_wiring.py` (new): fast, sim-free unit
  tests for `classify_domains`, `chromosome_state_from_live`,
  `rnaps_from_live`, and the `pack_from_state`/`EcoliPackStep.update()`
  wiring (entryState filtering, fork-fraction math, daughter classification,
  backward-compatible defaults).

## Key correctness points verified
- `active_RNAP`/`active_replisome`/`chromosome_domain` are registered
  `unique_array` domain types (same family as `full_chromosome`) — confirmed
  in `v2ecoli/library/schema_types.py`, and confirmed the store paths
  (`["unique", <name>]`) against `v2ecoli/composites/_helpers.py` and
  `v2ecoli/processes/transcript_elongation.py`.
- Live unique-molecule stores are read RAW by a Step (no automatic
  `_entryState` filtering — confirmed in
  `v2ecoli/types/unique_numpy.py`/`apply` dispatch), so `n_chromosomes` and
  fork/RNAP row selection filter `_entryState` explicitly, matching
  `v2ecoli/bridge.py::_read_chromosome_state` and
  `scripts/capture_structural_snapshot.py::_extract_snapshot` on the
  reference branch.
- `fork_fraction` is derived the same way `capture_structural_snapshot.py`
  does: `mean(|active_replisome.coordinates|) / REPLICHORE_BP`.
- Confirmed in the parsimony Rust engine
  (`parsimony/crates/parsimony-core/src/placer.rs`): when `chr.rnaps` is
  non-empty, the `rnap_marker` ingredient is EXCLUDED from the count-based
  random scatter (`skip_rnap_in_random`) — so the existing CURATED
  `rna_polymerase` count (2000) does not double-place; explicit RNAP loci
  fully replace the generic scatter once live data is available. When no
  RNAP data is available, it falls back to the prior generic scatter (no
  double-count, no missing RNAP either way).
- Confirmed the diffuse/theta routing: `n_chromosomes==1 &&
  fork_fraction<=0.0` is the ONLY branch that uses the diffuse
  self-avoiding-walk nucleoid; any replication in progress
  (`n_chromosomes>=2` or `fork_fraction>0`) routes through the theta
  (structured, replicated) layout — documented as a `# NOTE:` in
  `pack_from_state` per the task's instruction; this is accepted as a known
  limitation, not fixed here.
- `fork_marker`/`oric_marker`/`ter_marker` reference ingredient ids
  (`replisome`/`oriC`/`terminus`) that have no corresponding curated
  `Ingredient` entry yet — confirmed in `placer.rs::seat_markers` this is a
  silent no-op (not a crash) when the marker name isn't found among the
  recipe's ingredients, matching the task's instruction to pass these
  through as specified.
