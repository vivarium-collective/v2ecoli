Claim

Can v2ecoli aggregate single-cell-plus-Division output into population-level biomass observables (total gDW, cell count) that are physically meaningful at the reactor scale (OD ≫ 1) — using a representative-sampling scaling factor (`cells_per_agent`) so the simulated lineage legitimately stands in for an N-cell population under the 0D well-mixed assumption?

Read-only aggregation under the 0D well-mixed assumption: simulating N representative cells and scaling by k=cells_per_agent is mathematically equivalent to N x k literal cells. Per-cell biology (DnaA, mu, cell_mass) is untouched (regression-guarded). od_to_gdw=0.34 (Beulig 2025). OD600 is COSMETIC; biomass_concentration_gL is canonical. At large k per-cell stochastic variance washes out — correct biology at high density but obscures heterogeneity (e.g. Beulig bistable expression).

Model change

Base model: v2ecoli.composites.ecoli_baseline

New processes:

  • PopulationAggregator (Step · req: req-1-population-aggregator)

New state variables:

  • population.total_biomass_gDW (float)
  • population.cell_count (float) # float, not int — cells_per_agent scaling can be non-integer
  • population.biomass_concentration_gL (float) # CANONICAL biomass observable
  • population.OD600 (float) # COSMETIC — derived from biomass_concentration_gL for plotting / OD-only comparisons

New parameters:

  • cells_per_agent = 1.0 (real cells per simulated agent)
  • od_to_gdw = 0.34 (gDW/(L·OD600))
  • reactor_volume_L = 1.0 (L)
  • fg_per_gram = 1e-15 (g/fg)

Read-only aggregation; does NOT modify per-cell state. The Division Step is unchanged. The reactor_volume_L parameter is a default for this phase; mbp-03 will replace it with the reactor composite's dynamic volume store. cells_per_agent is the load-bearing knob; see purpose.mechanism for the rationale. The cell-side interface contract will be amended in a follow-up edit to reference the scaling discipline as part of the interface — engines either operate at literal scale or declare an explicit cells_per_agent factor.

Implementation requirements (2 items)

Concrete pieces of work that gate this study from Design → Build. Each generates a task.

req-1-population-aggregator — PopulationAggregator Step S [process]

PBG Step that walks `agents.*.listeners.mass.cell_mass`, sums, and writes: population.total_biomass_gDW = sum(agents.*.cell_mass) × cells_per_agent × 1e-15 population.cell_count = len(agents) × cells_per_agent (float, not int) population.biomass_concentration_gL = total_biomass_gDW / reactor_volume_L population.OD600 = biomass_concentration_gL / od_to_gdw NO mutation of agent state (regression-guarded by per-cell-observables-unchanged-vs-baseline and per-cell-observables-invariant-under-scaling). The cells_per_agent scaling factor is applied ONLY to the population.* outputs — never to per-cell stores. Hooks into the emit cycle so it runs once per emit interval.

Unblocks: all mbp-02 behavior_tests

req-2-population-composite — v2ecoli.composites.ecoli_population XS [composite]

Thin wrapper around v2ecoli.composites.ecoli_baseline that adds the population store + PopulationAggregator Step. Default reactor_volume_L = 1.0; overridden by mbp-03's coupling composite.

Unblocks: all mbp-02 simulations

Plan & assumptions

Pipeline gate

Each study is a model-building gate: it answers "Can we safely build the next layer?"

Prerequisites: none (root study)
Proceed when: cell_count and total_biomass_gDW track Division events (with cells_per_agent=1.0 default); per-cell observables match the unaggregated baseline (regression guard); single-cell-only sim (Division disabled) still works; pure consistency invariants hold at every emit step (population_count_equals_len_agents, total_biomass_equals_sum_cell_mass_times_scale); scaling-factor sweep sim at cells_per_agent ∈ {1, 1e6, 1e9} confirms aggregator output scales linearly and per-cell observables remain unchanged.

Key assumptions

  • Population is well-mixed (all agents see the same reactor liquid). This assumption is what makes the cells_per_agent representative-sampling factor mathematically equivalent to literal-N simulation.
  • Per-cell stochastic variance becomes negligible at large cells_per_agent (correct biology at high density; explicit cost of the representative-sampling choice — see chris_feedback_2026_05_26 §4).
  • od_to_gdw = 0.34 gDW/(L·OD600) per Beulig 2025 (was textbook 0.33).
  • cell_mass listener units are fg (femtograms) per v2ecoli convention.
  • PopulationAggregator runs as a Step at emit cadence; no need for inter-process synchronization.
  • OD600 is a COSMETIC observable (for plotting / OD-only data comparison); biomass_concentration_gL is canonical.

Limitations

What this study explicitly does NOT validate (prevents overclaim).

  • All agents share the same external environment in this phase (no per-cell microenvironment heterogeneity).
  • OD600 conversion is a constant factor; physical OD depends on cell size + scattering — may need regime-dependent refit (Beulig 2025 high-density regime). Less load-bearing now that OD600 is cosmetic.
  • Aggregator runs at emit cadence; not suitable as a feedback signal to processes that need sub-step granularity (deferred).
  • cells_per_agent scaling washes per-cell stochastic variance at large k — correct biology at high density (population averages dominate), but at k ~ 10-100 may obscure biologically-interesting per-cell heterogeneity (e.g. Beulig 2025's bistable expression states). Setting k is a calibration decision per investigation; see open_question scaling-factor-sets-stochastic-floor.
  • Single-cell-with-Division at small cells_per_agent does not scale to reactor densities (~10^13 cells/L at 50–80 gDW/L) by literal-N simulation. The scaling factor lets the SIMULATED N stand in for a larger M = N × k, sufficient for batch-phase work but with the stochastic-floor caveat above. A coarse-grained surrogate engine under the cell-side interface contract remains the path forward for the full high-density regime (mbp-06 scope; see candidate-future-study `mbp-08-surrogate-engine-for-high-density`).
