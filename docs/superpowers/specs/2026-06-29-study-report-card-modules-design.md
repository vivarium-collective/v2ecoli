# Per-study report-card modules — design

**Status:** approved design (2026-06-29), pending spec review → implementation plan.

## Goal

Every v2ecoli study shows **at least one report card** on its dashboard
detail page, generated by the **existing** modular report-card library
(`v2ecoli/library/report_card.py`). Report cards are **pluggable modules**:
the default-tests card is one module; the v2ecoli↔vEcoli equivalence card is
another; studies can add or remove modules, and adding a third kind later is
just registering a new module. Existing study pages look about the same —
they simply gain populated card slots and room for more.

## Background / current state

- The dashboard surfaces per-study cards from
  `workspace/studies/<name>/viz/report_card/<card>.html` (+ optional
  `<card>.verdict.json`, whose `.overall` field drives the verdict pill).
  Discovery is already implemented in
  `vivarium_dashboard/lib/saved_visualizations.py` and
  `lib/study_spec.py` (`report_card_urls`), and `publish.py` already stages
  `viz/report_card/` into the read-only bundle. **No dashboard changes are
  required.**
- **No study currently has a `viz/report_card/` directory** — so those slots
  render empty. That is the gap.
- The modular library already exists and is reference-driven:
  - `grade_card(card, reference) -> {overall, axes}`
  - `verdict_json(report, *, model_ref, reference_model, generated) -> {schema, overall, groups}`
  - `render_html(card, reference, *, model_ref, generated) -> html`
  - `card_criteria.grade_axis(measured, criterion)` with typed criteria
    (`rel_tol`, `ttest`, `r2`, banded scalars, …).
  - A `reference` is `{title, status, stimulus, findings, axes}` where
    `axes = {dotted_path: {group, label, units, criterion, …}}`; the `card`
    is a nested dict whose values `dig(card, path)` extracts.
- The v2ecoli↔vEcoli comparison is a **reference *mode*** (`vs_vecoli`) of a
  card. A cached vEcoli basal reference already exists at
  `docs/report_cards/population_phenotype_basal/vs_vecoli/vecoli_reference.json`
  — so a basal equivalence card grades with **no new AWS runs**.
- The comparison harness
  (`scripts/comparison_harness.sh`, `scripts/comparison_report_card.py`,
  `scripts/launch_full_comparison.sh`) launches fresh GovCloud S3 runs across
  5 conditions (`basal with_aa succinate no_oxygen acetate`). That path is
  **Phase 2** (incremental runs), not required for Phase 1.

## Approach (chosen: A — thin adapter over the existing library)

A small **card-module registry** plus a generator CLI. Each module delegates
all grading and rendering to `v2ecoli/library/report_card.py`; no new grading
or rendering logic is introduced. This mirrors how
`scripts/_compare/report_card_section.py` and
`scripts/pin_vecoli_equivalence_reference.py` already call the library.

Rejected alternatives:
- **B — extend `comparison_report_card.py` to also emit per-study.** Couples
  per-study cards to the S3/GovCloud pipeline; heavier; conflates Phase 2 with
  Phase 1.
- **C — new standalone renderer.** Duplicates the established method, which we
  explicitly want to reuse.

## Architecture

```
scripts/study_report_cards.py            ← generator CLI
  └─ uses scripts/_cards/                 ← module registry (new package)
       ├─ __init__.py     REGISTRY: {name: CardModule}; register(); applicable(study)
       ├─ base.py         CardModule protocol + StudyContext + write helpers
       ├─ tests_card.py   "tests" module    (applies to EVERY study)
       └─ vs_vecoli_card.py "vs_vecoli" module (applies when reference+data exist)
  emits → workspace/studies/<name>/viz/report_card/<module>.html
                                          + <module>.verdict.json
```

### Module contract

```python
class CardModule(Protocol):
    name: str                                   # filename stem (e.g. "tests")
    def applies(self, ctx: StudyContext) -> bool: ...
    def build(self, ctx: StudyContext) -> tuple[dict, str] | None:
        """Return (verdict_json_dict, html_str), or None if nothing to emit."""
```

`StudyContext` carries: `study_name`, `study_dir: Path`, `spec: dict` (parsed
`study.yaml`), and lazy accessors for run data (`run_zarr_paths()`) and the
workspace root. Modules read what they need; missing data → `applies()` is
False (skip) rather than an error.

### Module selection per study

- A study may declare `report_cards: [tests, vs_vecoli]` in `study.yaml`
  (optional new key).
- **Default when the key is absent:** emit every registered module whose
  `applies(ctx)` is True. The `tests` module applies to every study, so the
  "≥1 card per study" guarantee holds with zero study-file edits.
- **Add a module:** register it (and optionally name it in a study's
  `report_cards:`). **Remove:** drop it from `report_cards:` (or it stops
  applying); the generator's `--prune` deletes stale `viz/report_card/*`
  artifacts no longer produced for that study.

### `tests` module (universal, run-free)

Maps the study's `tests:` block to a single-group report card:

- One **axis per test**, path `tests.<slugged-test-name>`.
- Presentation: `group` = the test `classification` (e.g. `primary`/`secondary`),
  `label` = test `name`, `detail` = `question` + `measure.detail`, plus a
  `cites` line when present.
- **Verdict source:** the test's recorded `status`
  (`passed → within_tol`, `failed → mismatch`, anything else → `ungraded`).
  We grade from the recorded status, not by re-evaluating against run data, so
  the card is producible for every study without runs.
- **Measured value:** if the study has a stored evaluated value for the test
  (from its existing test evaluation output), include it for display;
  otherwise render verdict-only. (Resolved in the plan; the card is valid
  either way.)
- `pass_if` (e.g. `{op: in_range, low, high}`) becomes the human-readable
  criterion string shown on the axis.

This is intentionally a faithful re-presentation of what the study already
asserts in its `tests:` block — the same information the dashboard's native
Tests section shows, now also as a gradeable, exportable card module.

### `vs_vecoli` module (equivalence, run-free to start)

Grades a study's run data against a cached vEcoli reference:

- `applies()` is True when **both** a `vs_vecoli` reference fixture and study
  run data are resolvable. Phase 1 target: studies with local data + a cached
  reference (basal). Reference resolution precedence:
  1. `study.yaml` `report_card_refs.vs_vecoli: <path>` (explicit), else
  2. the conventional cached fixture for the study's condition
     (`docs/report_cards/<card>/vs_vecoli/vecoli_reference.json`).
- Builds the measured `card` from the study's run zarr via the existing
  readers (`v2ecoli.library.card_vectors` / the `_compare` readers already
  used by `report_card_section.build_report_card`), then calls
  `grade_card` / `verdict_json` / `render_html`.
- Emits `vs_vecoli.html` + `vs_vecoli.verdict.json`.

## Data flow

```
study.yaml + run zarr ──► StudyContext
   for each applicable module:
      module.build(ctx) ──► (verdict_json, html)   [library grade_card/render_html]
      write viz/report_card/<module>.html
      write viz/report_card/<module>.verdict.json
dashboard (unchanged) auto-discovers the files ──► study-detail page + Tests module
publish.py (unchanged) stages them into the read-only bundle
```

## Phasing

- **Phase 1 (this spec → one implementation plan): wire + universal coverage,
  no new runs.**
  1. Card-module registry + `StudyContext` + write/prune helpers.
  2. `tests` module → emit for **all** studies.
  3. `vs_vecoli` module → emit for showcase-2-baseline-figures (local data)
     and any study with cached reference + data.
  4. Generator CLI (`--study all|<name>`, `--card all|<name>`, `--prune`).
  5. Verify cards render on the live dashboard and in the published read-only
     bundle.
- **Phase 2 (incremental, not in this plan): expand equivalence runs.** Drive
  `comparison_harness.sh` / `launch_full_comparison.sh` on GovCloud for the
  remaining conditions as AWS is authorized; regrade; refresh `vs_vecoli`
  cards. Adding a new comparison kind = registering a new module.

## Error handling

- A module that cannot build (missing reference, unreadable zarr, malformed
  test) logs a skip and continues; it never aborts the whole generation run.
- `verdict.json` is written only alongside a successfully rendered `html`.
- `--prune` removes only artifacts under `viz/report_card/` whose stem is not
  produced this run for that study (never touches other `viz/` subdirs).
- Non-finite floats are sanitized before JSON write (the published bundle
  rejects `NaN`/`Infinity`).

## Testing

- **Registry/selection:** `applies()` truth table — `tests` applies to a
  minimal study; `vs_vecoli` skips when no reference/data, applies when both
  present (fixture).
- **`tests` module:** a fixture `study.yaml` with passed + failed tests →
  one axis each, correct verdicts, `overall` = worst, valid
  `report_card_verdict/v1` JSON.
- **`vs_vecoli` module:** a tiny fixture reference + a tiny measured card →
  `grade_card` produces expected axis verdicts; html + verdict.json written.
- **CLI / wiring:** running the generator against a fixture workspace creates
  `viz/report_card/tests.html` + `.verdict.json`; the dashboard
  `saved_visualizations` / `study_spec.report_card_urls` readers pick them up
  (assert via the existing dashboard reader functions or a served fixture).
- **Prune:** stale artifact removed; sibling `viz/` dirs untouched.

## Out of scope

- No dashboard frontend/back-end changes (the readers and publish staging
  already exist).
- No new GovCloud runs (Phase 2).
- No change to the existing native Tests section; the `tests` card is an
  additional, exportable representation, not a replacement.
